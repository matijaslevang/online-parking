
# Project Instructions

## Code Quality and Readability

- Prioritize clarity, simplicity, and maintainability over cleverness or brevity.
- Write code that is easy to navigate, understand, and explain.
- Use descriptive and consistent names for files, functions, variables, and types.
- Keep functions focused and code flow explicit.
- Avoid complex expressions, unnecessary shortcuts, and hard-to-read syntax sugar.
- Avoid unnecessary abstractions, layers, helper functions, design patterns, and dependencies.
- Organize code predictably so that every feature and responsibility is easy to locate.
- Minimize comments. Prefer self-explanatory code. Add comments only to explain non-obvious decisions or constraints.
- Avoid unnecessary boilerplate and premature optimization.

## Communication

- Keep responses short, direct, and focused.
- Avoid lengthy explanations, summaries, and step-by-step descriptions unless explicitly requested.
- After making changes, briefly explain what changed.
- Mention only important decisions, issues, or next steps.

## Git Commit Conventions

Follow the Conventional Commits specification.

Format:
`<type>(<scope>): <description>`

Allowed types: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `ci`, `perf`, `style`.

Examples:
- `feat(psp): implement payment initialization`
- `fix(bank): prevent duplicate charges`
- `refactor(parking): simplify session validation`
- `chore: initialize monorepo`
- `docs: add system architecture diagram`
